# RL Atlas：教学路径、原文分析与网页设计

> 后续图解更新：本站已将 Mermaid 展示替换为 21 张生成式学术概念图，保留这份历史设计/生成/验证记录。当前接口、双语读图说明和导出规则见 [concept-plates.md](concept-plates.md)。下文的历史图源或解析记录不代表当前页面仍运行绘图引擎。

## 1. 这份教程要解决的问题

学习者往往能运行一个现成 PPO 示例，却难以解释它为什么适合自己的任务，也不确定状态、奖励、终止条件和实验指标是否写对。本教程把这些问题放进同一条学习路径：理解决策问题，建立最小数学模型，辨认算法解决的瓶颈，计算一个可检查的例子，再通过实验形成证据。

本项目针对已有神经网络基础、希望补齐强化学习概率直觉并连接流程工业研究的学习者。通用基础完整保留；工业专题围绕“当前工况 → 未来 CV 设定值增量”，不把主线改写成 LLM 后训练课程。

## 3. 课程如何从七个模块长成完整教程

### 概念先形成联系，再引入算法名称

模块一先建立交互、长期回报和探索的语言。模块二把这些直觉变成 MDP 与价值更新。模块三用“表格装不下”和“移动的学习目标”解释 DQN 的出现。模块四从直接调整概率走向优势估计和 PPO。模块五处理连续动作、密度和最大熵。模块六要求学习者独立定义问题并说明实验可信度。模块七再讨论固定日志、世界模型和约束研究。

这个顺序使“为什么出现”有明确上下文。例如 Double DQN 接在最大化偏差之后；GAE 接在高方差策略梯度之后；离线 RL 接在覆盖和数据来源之后。读者可以用已有问题检验新算法，而不必先记住一串名称。

### 每章需要完成的教学闭环

| 环节 | 设计要求 | 可验收内容 |
|---|---|---|
| 动机 | 指出上一种方法的局限 | 能用自己的话说出本章解决什么 |
| 定义 | 统一符号、时间索引和假设 | 能识别状态、动作、奖励与数据来源 |
| 推导 | 解释公式每一项的作用 | 能拆开目标，判断符号与边界 |
| 数值例子 | 使用可手算的小规模数据 | 浏览器或脚本结果与手算一致 |
| 实现 | 给出核心代码或数据流 | 知道哪些张量需要停止梯度 |
| 失败情形 | 说明什么时候结论不成立 | 不把工程技巧说成普遍保证 |
| 练习 | 先思考，再展开答案 | 能解释错误来自哪里 |
| 来源 | 指向具体原始资料 | 可进一步核验和深读 |

阅读时长是建议估计，不以原推文宣传的课程时长作为本教程工作量。网站的 6/8 周计划围绕交付物安排，也不以浏览页面数量替代掌握程度。

## 4. 技术准确性上的补充与纠正

| 容易产生的简化理解 | 教程采用的精确表达 | 核验依据 |
|---|---|---|
| 奖励下标随手写即可 | 通用章节使用转移奖励约定；工业规范沿用下标时明确转换关系 | [Sutton & Barto](https://incompleteideas.net/book/the-book-2nd.html) |
| 超时和任务结束都叫 done | 自然终止关闭自举，外部截断保留最终观测的自举 | [Gymnasium 时间边界](https://gymnasium.farama.org/tutorials/gymnasium_basics/handling_time_limits/) |
| SARSA 总是更安全 | 悬崖例子的差异依赖探索策略和评价设定，不是普遍安全证明 | [Sutton & Barto](https://incompleteideas.net/book/the-book-2nd.html) |
| 回放会让数据完全独立 | 抽样改变数据使用方式，仍受相关性、覆盖和有限缓冲区影响 | [DQN 原论文](https://www.nature.com/articles/nature14236) |
| Double 方法消除所有价值误差 | 分开选择和评价针对特定最大化偏差，仍存在其他估计误差 | [Double DQN](https://arxiv.org/abs/1509.06461) |
| GAE 只需要一个 done mask | 价值自举与跨 episode 残差递推分别处理 | [GAE](https://arxiv.org/abs/1506.02438)、[Gymnasium](https://gymnasium.farama.org/tutorials/gymnasium_basics/handling_time_limits/) |
| PPO 的概率比不会超过裁剪范围 | 裁剪代理目标取消部分继续更新的激励，不是硬概率比或 KL 约束 | [Spinning Up PPO](https://spinningup.openai.com/en/latest/algorithms/ppo.html) |
| tanh 之后仍用高斯原密度 | 加入变量变换的 Jacobian；物理缩放需要一致的密度坐标 | [SAC](https://arxiv.org/abs/1801.01290) |
| 高熵意味着安全 | 熵影响探索与优化，物理边界由成本、门控和执行系统另行处理 | [SAC](https://arxiv.org/abs/1812.05905)、[CPO](https://arxiv.org/abs/1705.10528) |
| 能离策略训练就能可靠离线训练 | 固定日志缺少交互纠错，必须考虑支持域与外推偏差 | [CQL](https://arxiv.org/abs/2006.04779)、[IQL](https://arxiv.org/abs/2110.06169) |
| 一条最优曲线足以排名算法 | 保留所有种子、明确实验单位与评估协议并报告不确定性 | [Statistical Precipice](https://arxiv.org/abs/2108.13264) |
| CMDP 约束代表每一步都安全 | 常见形式限制期望累计成本，不自动提供逐步硬边界保证 | [CPO](https://arxiv.org/abs/1705.10528) |
| 教学推演能代表现场收益 | 只报告模拟机制与假设；真实收益需要正式数据和现场验证 | [项目契约](../../AGENTS.md) |

这些澄清嵌入相关章节与练习，而不是放在读者很少看到的附录。所有图和交互解释应与同一套约定一致。

## 5. 实验如何支持学习

14 个实验分成三类。第一类直接计算公式，例如折扣回报、Bellman、GAE 与 PPO；它们让符号变成能逐项核对的数。第二类进行小型随机学习或 Monte Carlo，例如老虎机、悬崖与最大化偏差；它们帮助观察采样和运行间差异。第三类展示工程逻辑，例如回放标量模型、连续策略密度与安全门控；这些演示明确标注简化范围。

实验采用真实计算，不播放预先设计的“算法收敛曲线”。同一 seed 可以复现本浏览器实现中的随机序列，但不声称与 NumPy/PyTorch 的序列逐位相同。对比时显示实验对象、横轴和参数含义，避免让用户误以为浏览器正在训练完整神经网络。

精确的实现边界见 [labs.md](labs.md)。纯数值内核集中在 `src/labs/math.ts`，界面层复用这些计算，便于以手算结果检查算法，而不是让测试仅重复界面代码。

## 6. 网页的信息架构

### 首页：知道在哪里、接下来做什么

左侧导航提供学习总览、课程目录、实验室、路线、笔记、资料与图册。首页首先展示教程主题和原创介绍图，再提供继续学习卡片、真实进度、模块入口与实验入口。用户完成章节后，进度更新；没有人为设置的学员数量或课程成效。

### 阅读页：长文仍然容易定位

章节标题区显示模块、前置知识和学习目标；中间正文承载推导、例子和实验链接；桌面右侧提供本章目录。公式保持数学渲染，宽公式与代码可以横向阅读，不强行缩成难读字号。练习答案使用可展开结构，支持先思考再核对。

Mermaid 图旁保留图源和 SVG 下载。图中的节点、边与标签来自可编辑代码；原创介绍插画用于建立视觉主题，不承担精确公式或数据图表的职责。

### 实验页：控制项与解释在一起

每个实验说明问题和可调变量，改变参数后重新计算结果，显示公式或机制解释。演示范围在界面和文档中一致。安全门控实验只做本地逻辑推演，交互按钮没有连接生产设备或外部写入。

### 笔记与学习状态

数据模型带版本号，加载时验证章节 ID 和字段类型。当前浏览器保存完成状态、收藏、笔记及阅读偏好；Markdown 笔记导出方便继续写作，JSON 导出用于迁移。导入采取合并策略，保留已有冲突笔记，减少误覆盖。

## 8. 工业主线的边界与下一步

案例沿用仓库定义的 5 分钟决策周期、有界六维设定值增量、历史窗口、软测量和化验年龄，并将质量与气体边界作为单独成本。五层门控、回退与下层 DCS/PID/APC 的职责分离。阈值被明确称为项目约定，不推广为任意工厂的工艺标准。

当前仓库缺少正式工业数据、世界模型权重和完整 PG-MOEA/D-IEpsilon 实现，所以教程交付的是有明确假设和接入要求的研究方案。后续的可信实验需要先获得可追溯数据与基线，再核对时间可见性、动作条件模型、成本尺度和独立测试工况。教学推演不填入真实节能结果表。

## 9. 内容维护原则

新增内容先说明它要回答的具体问题，再补原始出处、最小例子与边界。新增实验同时说明实际计算和没有实现的部分。调整源码后更新完整 Markdown 导出，使网站和长文保持同源。数值、内容、浏览器与手工阅读各自负责不同的错误类型，验证结论应来自实际运行记录。
