# 中文图与交互公式案例：设计、实现及验收

日期：2026-11-14。该版本接续原始概念图迁移，解决“中文正文仍显示英文图片”，并把公式计算接入实际阅读过程。

## 1. 图片的语言现在由当前版本决定

原先的注册表提供中英文标题、图注和读图说明，但两种版本引用同一个英文 WebP。仅翻译图片外的文字无法改变图内的标题和标签。因此本次新增实际包含中文文字的图片，并统一选择图片版本的规则。

| 内容 | 中文版本 | 英文及其他图片语言请求 |
|---|---|---|
| 11 张章节概念图 | `public/images/diagrams/zh-CN/chapter-XX-diagram-1.webp` | 原英文文件 |
| 9 张研究概念图 | `public/images/diagrams/zh-CN/research-ID-diagram-1.webp` | 原英文文件 |
| 学习路线图 | `public/images/diagrams/zh-CN/roadmap-learning.webp` | 原英文文件 |
| journey 插图 | 书页文字为“强化学习图谱”的中文版本 | 原英文版本 |
| 其他 6 张场景插图 | 无需翻译的画面及数字区域标记，共用原图 | 同一原图 |

新增 **22 张中文 WebP，共 3,090,892 字节**。21 张概念图均为 **1536 × 1024**；journey 保持 **1672 × 941**。原英文文件未被覆盖。图库保持 **28 个稳定条目**，两种图片版本合计 **50 个独立资源文件**；站点标志不计入图库。

所有中文图都用 imagegen 逐张编辑，检查了中文标签、箭头关系、终止/截断、请求/执行动作、奖励/独立约束等语义。标准算法名和数学符号按学术惯例保留。逐图提示词、原图、生成源、尺寸、哈希及文字审查记录见：

- [中文课程图片记录](diagram-assets/chinese-course-generation.json)
- [中文研究与路线图片记录](diagram-assets/chinese-research-generation.json)

`src/image-locales.ts` 负责图片语言：`zh` 与 `zh-*` 请求选择简体中文图片，其他请求选择英文。当前完整界面语言仍为 `zh-CN` 和 `en`；图片 fallback 不代表已经新增其他界面语言包。显式传入的 locale 优先于环境中的当前语言，避免生成英文教材时意外引用中文图。

该规则覆盖章节、研究文章、学习路线、图库列表和详情、放大查看、打开原图、WebP 下载、单章下载和六份完整导出。下载名带 `.zh-CN.webp` 或 `.en.webp`，便于区分版本。语言切换重新渲染页面时关闭旧查看器。

### 导出解析一并修复

审查发现旧的独占行匹配会漏掉行内图片，而且同一行放两张图时，贪婪匹配可能吞掉第一张。本次分开处理“选择图片语言”和“扩展独立概念图读图说明”：

- 每个注册图片引用都按版本重写，同行多图保持原数量和顺序。
- 只有独占一行的概念图扩展完整读图说明，行内图不被强行变成大段内容。
- `mapMarkdownProse` 保护反引号/波浪线代码围栏、缩进代码和反引号代码片段，避免改写示例本身。
- 可信控件仍只接受精确注册的本地资源路径；未知 ID、任意语言目录、外部 URL、路径穿越及重复语言目录均不获得图解控件。

## 2. 从阅读公式到实际计算

新增独立的 **“公式案例计算”** 入口：`#/cases`。每个案例也有稳定地址 `#/cases/{id}`，并接入首页、全站搜索、相关章节和研究专题。

每个案例包含背景、带单位的输入、三组预设、原始公式、数值代入、分步解释、结果以及来源。输入后即时重算，可以重置或导出当前参数对应的 Markdown 算例。总计 **10 个双语案例、30 套情景预设**。

| 案例 | 可研究的问题 | 默认计算核对 |
|---|---|---|
| 三步回报 `return-bootstrap` | 时间截断是否应去掉末状态价值？ | 观察回报 3.23，尾部 2.916，目标 **6.146**；真正终止目标 **3.23** |
| Bellman 期望 `bellman-expectation` | 同一动作的两个可能后果怎样加权？ | 两分支贡献 5.25、−0.33，目标 **4.92** |
| TD 更新 `td-update` | TD(0)、SARSA、Q-learning 的自举值有什么不同？ | 默认 SARSA 更新到 **1.58**；切换 Q-learning 为 **2.12** |
| GAE `gae` | 后续 TD 残差怎样传回当前优势？ | 三个优势 **2.84432、2.006、2.3** |
| PPO 裁剪 `ppo-clip` | 优势为负时，生效的裁剪方向如何改变？ | 正优势目标 **2.4**；负优势预设目标 **−1.6** |
| SAC 目标 `sac-target` | 双 Q、熵温度与 log 密度怎样组成目标？ | 默认 **6.1876**；正 log 密度预设 **5.851** |
| 离散 CQL `cql-regularizer` | 未记录动作的高 Q 值为何影响保守项？ | 保守差值约 **3.065884**，总教学损失约 **3.190884** |
| 设定值与响应 `setpoint-response` | 动作改变 SP 后，PV 为何没有立即到位？ | 接受请求后 PV **879.56°C**；拒绝后仍演化到 **879.28°C** |
| 能耗奖励 `energy-reward` | 奖励好看时，是否仍可能存在独立约束越界？ | 默认奖励 **0.375**；越界预设保持奖励、分别报告成本 |
| 约束权衡 `constraint-lagrangian` | 松弛目标选出的策略一定满足预算吗？ | 松弛排序选 **A**，预算可行排序选 **B**，乘子更新为 **2.1** |

完整数学约定、输入含义、手算过程和原始文献核对见 [公式案例说明](formula-cases.md)。这些是确定性的教学计算；设定值、质量及氧含量等参数沿用现有教学模型的定义。

### 放在读者需要计算的位置

章节中的学习顺序增加“改参数，算公式”。案例区位于情景推导与系统正文之间，并有直接跳转按钮。若一章对应多个案例，用选择器切换单个计算面板，避免连续堆放大型表单。研究文章也在相关主题下提供对应计算，并在目录中给出入口。例如：

- 第 01 章：三步回报、设定值与过程响应。
- 第 15 章：GAE、PPO。
- 第 17 章：SAC。
- 第 21 章：设定值响应、能耗奖励。
- 第 24 章：奖励分解、约束权衡。
- 研究“目标与约束”：能耗奖励、拉格朗日权衡。

原有 8 个数学准备计算器、14 个实验和水泥工作台继续承担各自的学习任务。新案例侧重把一条公式算清楚，并解释每个输入对结果的影响。

## 3. 数值与交互的具体取舍

### 先保证计算语义，再显示结果

终止和外部截断使用不同的尾部处理；GAE 的 bootstrap 掩码与轨迹边界掩码分开。PPO 在乘以优势后取两个目标项的最小值，覆盖正、负优势。SAC 接受连续密度大于 1 时的正 log 密度。CQL 明确限定为有限离散动作教学损失，并使用稳定的 log-sum-exp。

工业案例保留请求增量与执行增量、SP 与 PV、奖励与独立成本的区别。拒绝请求会保持 SP，过程仍继续响应。拉格朗日案例将松弛排序、预算可行性和乘子更新分别显示；平均成本预算并不替代逐步执行门控。

### 输入与显示保持一致

空值、非有限值、越界值和伪造选择值都不产生成功结果。无效输入会隐藏旧结果并禁用下载。渲染也采用原子更新：先完整生成公式、结果和播报文本，成功后才提交页面及可导出快照；渲染异常同样清除旧结果。

计算使用完整浮点精度，展示通常保留最多六位小数，极小/极大数使用科学计数法。独立审查发现科学计数法作为幂底数时会出现 KaTeX 双上标错误，现已整体分组并覆盖 `γ=10⁻⁷` 回归测试。

数字输入不会因结果更新而失去焦点。所有字段都有标签、帮助和错误关联，结果变化通过 live region 播报。长公式和表格在各自区域内滚动。静态导出明确区分“起始案例背景的默认参数”和“本次计算输入”，防止修改参数后背景数字被误认为当前值。

## 4. 导出与内容保留

六份中文/英文教材和研究综述已经重新生成。相关位置包含案例的默认输入、公式、代入、结果、解释和来源。单章下载也包含该章对应的案例。当前算例的独立下载保存用户当时输入的数值。

这些 Markdown 文件保存完整静态计算过程，交互计算在网页中进行。完整离线图片阅读仍需保留仓库的配套图片目录；单章下载使用仓库主分支的在线图片 URL。重复出现的案例不会引入重复 HTML 锚点或无法使用的网页 hash 链接。

原有 24 章、7 个模块、24 组导读/154 个推导步骤、8 个数学单元、36 条术语和9篇研究专题继续保留。验证确认 67 个既有正文指纹及 3 个数值核心指纹不变；本次未重写旧正文或修改模拟器常量、阈值和状态维度。

## 6. 使用边界与后续扩展

当前案例为确定性的示例计算，不提供训练服务、外部模型 API 或现场数据。图像表达概念，精确关系仍由可选择的数学公式与文字定义。现有的语言切换会重新挂载页面并恢复案例预设；要保留已编辑输入，可以先导出当前算例。增加其他界面语言时，可继续复用英文图片策略；若新增带文字插图，需要为中文登记对应资源，并同步扩展图片和导出验收。
